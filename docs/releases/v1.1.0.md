# Vector Engine v1.1.0

## Release summary

v1.1.0 continues Vector Engine as a reproducibility-first Python library for local retrieval experimentation, with stable API contracts, contract-validated artifacts, and publication-oriented evaluation workflows.

## Patch notes

### Included fixes from v1.0.2

- `retrieval_report_detailed(..., include_error_buckets=True)` computes `zero_hit_rate@k` and `perfect_recall_rate@k` over queries that have non-empty ground truth.
- `no_ground_truth_rate@k` continues to use total-query denominator so missing-label prevalence stays visible.
- This is a semantics correction for mixed query sets (labeled + unlabeled) and does not change API names or output keys.

## Stable public surface

- Core: `VectorArray`, `VectorIndex`, `Metric`, `SearchResult`
- ML: `kmeans`, `KMeansResult`, `knn_classify`, `knn_regress`
- Training: `mine_hard_negatives`, `TripletBatch`
- Eval: `retrieval_report`, `retrieval_report_detailed`, `batch_metrics_summary`, `retrieval_cohort_report`

See `docs/api_stability.md` and `tests/test_api_stability.py`.

## Highlights

- Reproducibility contract pipeline via `artifact_contract_version`
- Dataset ingest/connectors pipeline with reproducible bundle manifests
- Matrix benchmarks with protocol and environment metadata
- Stability-study summaries with spread metrics (`std`, `cv`, intervals)
- Credibility audit flow for evidence-quality checks

## Caveats and scope boundaries

- This project does not claim a new ANN algorithm.
- Performance outcomes are configuration and hardware dependent.
- Private embeddings and sensitive metadata must remain outside public artifacts.

See `docs/limitations.md` and `docs/credibility_audit.md`.

## Migration notes (from v0.3.x)

- No intentional breaking changes in core public API.
- v1.1.0 continues API stability and reproducibility contracts.
- Existing v0.3 workflows remain usable, with additional artifact validation and release packaging.
